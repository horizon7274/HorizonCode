# HorizonCode — Spec v0.2：工具系统

## 背景

v0.1 已完成终端中的流式对话、历史记录和 Anthropic/OpenAI 双 Provider。本版本让模型能够请求由 HorizonCode 执行的受控本地操作，并把执行结果保存到对话中。这样模型可阅读、搜索和修改当前项目，并在需要时请求运行命令。

## 目标用户

在终端中开发、希望让 AI 协助理解和修改当前项目代码的开发者。

## 目标

在保持现有流式聊天体验的前提下，建立可扩展、安全且同时兼容 Anthropic Messages API 与 OpenAI Chat Completions API 的工具调用闭环。

## 能力清单（P0 — 本次交付）

1. **统一工具契约**：每个工具提供名称、面向模型的描述、JSON 参数 Schema 和异步执行能力。
2. **核心文件工具**：模型可读取、写入和按唯一原文匹配修改当前项目内的文本文件。
3. **核心搜索工具**：模型可按 glob 模式列出项目文件，也可搜索代码文本并得到文件位置和上下文。
4. **受控命令工具**：模型可请求在当前项目目录执行命令；每条命令都必须经用户在终端中确认后才会运行。
5. **集中注册与导出**：工具由单一注册中心维护，可按名称查找，并能生成两种 Provider 所需的工具声明。
6. **结构化执行结果**：工具成功、参数错误、越界访问、超时、命令拒绝和运行失败都以统一的结构化结果记录，供后续对话使用。
7. **流式工具调用解析**：两个 Provider 均能拼接流中分片到达的 JSON 参数，产出完整的工具调用请求。
8. **一次响应内的独立调用**：模型一次响应可请求多个工具；HorizonCode 按请求顺序执行并记录所有结果，但不基于结果再次请求模型。
9. **工具结果回灌历史**：模型发出的工具调用和对应结果都写入会话历史，并在下一次用户提问时发送给对应 Provider。

## 非功能要求

- **作用域隔离**：所有文件操作、glob 和内容搜索只能访问启动时确定的项目根目录及其子路径；解析后的路径不得逃逸该目录。
- **命令授权**：命令默认不执行。每次请求必须向用户展示完整命令、工作目录和超时，且只有明确同意后才执行。
- **失败可恢复**：工具失败不得中断 TUI 或丢失已经收集的其他工具调用；结果应包含机器可读的失败类别和人可读说明。
- **输出有界**：文件内容、搜索结果和命令输出均要限制体积，避免单次工具结果挤满终端或 API 上下文。
- **超时可控**：每项工具执行都须受超时保护；超时后返回结果而不是卡住会话。
- **兼容性**：继续支持当前 Anthropic Messages API 和 OpenAI Chat Completions API 的流式文本回复与工具调用。
- **可测试性**：文件系统、子进程和确认提示应通过可替换边界测试，无需真实 API 密钥或执行危险命令。

## 设计骨架

```
用户消息
   │
   ▼
TUI / 会话历史 ──▶ Provider（流式文本 + 工具调用分片）
                           │
                           ▼
                     完整工具调用列表
                           │
                           ▼
              工具注册中心 ──▶ 路径守卫 / 确认提示
                           │
                           ▼
                  统一工具执行结果
                           │
                           ├──▶ 终端展示
                           └──▶ 会话历史（下一轮请求携带）
```

- **工具层**：定义一个统一抽象和共享结果格式；六个核心工具各自独立实现，注册中心负责发现和 API 工具声明转换。
- **路径层**：以 HorizonCode 启动目录为项目根目录；所有相对路径先规范化再校验是否仍在根目录内。
- **执行层**：普通文件/搜索工具直接执行；命令工具经 TUI 的逐条确认后在项目根目录执行。写文件和编辑文件是有状态操作，但不要求额外确认。
- **Provider 层**：统一输出文本帧、完整工具调用帧、错误帧和完成帧；各 Provider 在内部处理协议差异及 JSON 参数分片。
- **历史层**：内部历史保留 Provider 所需的原始工具调用关联信息；生成下一轮 API 请求时分别转换成 Anthropic 的 tool-use/tool-result 内容块和 OpenAI 的 assistant tool_calls/tool 消息。
- **交互层**：一轮模型响应结束后，执行其中全部独立工具调用，展示结果并返回输入提示；不进入“结果再喂模型继续决策”的循环。

## 完成定义

用户可以在项目根目录启动 HorizonCode，提出需要文件或命令操作的问题；当兼容的模型在一次流式响应中请求一个或多个核心工具时，HorizonCode 能正确解析、在安全边界内执行、对命令征求确认、展示并持久化结构化结果。下一次用户提问会携带这些结果，两个 Provider 均保持可用。

## Out of Scope

- 根据工具结果自动再次调用模型的 Agent Loop
- 多轮自动规划、重试或任务队列
- MCP 协议、第三方工具市场和动态加载外部插件
- 项目根目录以外的文件访问
- 命令白名单、沙箱容器、权限策略持久化或“始终允许”授权
- 二进制文件读写、图片/PDF 内容解析和大文件分块编辑
- Git 专用工具、网络请求工具、浏览器自动化工具
- 多用户协作、审计服务或远端命令执行
