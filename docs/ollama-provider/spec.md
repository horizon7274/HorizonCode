# Ollama 原生 Provider

## 背景

HorizonCode 已支持 Anthropic 与 OpenAI 协议的远程模型，但用户无法通过同一终端交互流程使用 Windows 上由 Ollama 托管的本地模型。

## 目标用户

已在本机安装并运行 Ollama，希望使用本地代码模型，并仍能使用 HorizonCode 文件与命令工具的开发者。

## 能力清单

- 用户可在配置中选择 Ollama 作为模型后端并指定本地模型。
- 程序可通过 Ollama 原生聊天接口获取流式思考与文本输出。
- 支持工具调用的本地模型可请求 HorizonCode 已注册的文件、搜索和命令工具。
- 工具执行结果会以 Ollama 所需的消息结构在后续对话中回灌给模型。
- 服务不可达、响应超时和服务端错误会在终端中以可理解的错误呈现，且不会导致程序崩溃。
- 示例配置与使用说明可让用户在 Windows 本机完成启动、选模和运行。

## 非功能要求

- 不新增运行时依赖，继续使用现有异步 HTTP 客户端。
- 所有本地 API 调用保持异步和流式，以维持终端响应体验与取消行为。
- 不发送鉴权头，且不记录用户模型输出以外的敏感配置内容。
- 新增功能应有不依赖已安装 Ollama 或真实模型的自动化测试。

## 设计骨架

在既有 Provider 注册机制中增加 Ollama 实现。该实现将统一的聊天输入、流式输出和工具调用转换为 Ollama 原生消息与响应格式；工具注册中心和历史管理器各增加对应协议的格式转换。主流程与 TUI 继续只依赖现有的统一 Provider 抽象。

## Out of Scope

- 自动安装 Ollama 或下载、删除模型。
- 从 HorizonCode 远程暴露 Ollama 服务。
- 图像、多模态输入、嵌入与结构化输出功能。
- 自动多轮工具代理循环；保持当前“执行工具后在下一次用户提问时回灌”的交互规则。
- 为不支持工具调用的模型模拟工具调用。
